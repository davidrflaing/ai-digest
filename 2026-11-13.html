Claude skills / plugins / MCP

  • [skill] Claude Code 2.1.323 (changelog, Nov 12) — four changes touch your setup. (1) "Fixed --permission-mode auto or a settings defaultMode: auto starting in a mode that could allow more when auto mode was unavailable. It now starts in Manual mode, which asks first". (2) "Fixed claude -p silently using another model in text output when settings block the requested one; it now warns on stderr". (3) "Changed how many messages each of your sessions on the same machine can send the others without a prompt from you, from about 20 to 100,000." (4) "Added Code Mode, an experimental opt-in in which Claude writes JavaScript to call its tools". Also: engines["claude-code"] in plugin.json (a plugin outside its stated version range isn't installed or loaded), /security-review now asks before it runs, and a heartbeat every 30 seconds while hooks run long in claude -p. Flags: this run read only the first part of the entry, so the bug-fix list is incomplete; nothing in the part read mentions the account-email check. Dave: any unattended claude -p job that relies on auto mode (this digest, consider-this, the nightly comms pass) now stops and asks if auto mode is unavailable, where before it could run looser. That is the safer failure, but it looks like a hung job, so check this morning's logs for a stall and for a new stderr model warning. The 100,000 figure removes a brake on lane-to-lane messages: the 🎯 Orchestrator's rules are now the only limit. Leave Code Mode off until the docs page is read. ↗
  • [skill] "MCP vs CLI vs Skills: What Each Costs in Context" (OpenRouter, Nov 11; in TLDR AI Nov 12) — one GitHub task, measured on Sonnet 5.5, median of three runs: CLI 1,421 input tokens (0.0075), askill3, 315(0.0118), MCP with 2 tools 23,228, MCP with the default 46 tools 59,417 ($0.1274), all 91 tools 101,351. Their advice: "Use a CLI when one exists and your agent can run commands. When it can't, use MCP, scoped and with small results." Flags: "We tested one server on one task"; OpenRouter sells the Tool Search feature the post promotes; Haiku 5.5 cost more with 46 deferred tools than with all loaded. Dave: it supports what you already do (the WhatsApp lane as three scripts, notion-tasks as five narrow tools). The check worth doing: your sessions carry the full GoHighLevel and Notion plugin tool lists as deferred tools, so the up-front cost is small, but the next MCP server you build should start as a CLI plus a skill unless a session can't run commands. They publish mcp_cost.py to measure your own. ↗
  • [skill] MCP Apps: app tools and embedded sites in Claude (Anthropic, Nov 10; public preview for developers) — "Claude now supports more of the extension, such as app tools, along with embedded sites, so a developer's full app can run inside Claude." A view can register up to 64 tools so Claude changes what is on screen; an embedded site loads in an iframe whose origin the server declares. Flags: app tools and embedded sites are limited to a set of organisations; custom connectors "may not get them in every conversation"; camera, microphone and clipboard-write are lost in views that embed sites. Dave: nothing to build yet. It is the route by which the portal or the reporting dashboard could one day open inside Claude for you, and it isn't dependable for a custom connector today. ↗ · ClaudeDevs

GitHub repos & OSS tools

  • [repo] Yogurt (FrigadeHQ/yogurt; MIT; 1.0k★; Show HN 290 / 111) — "Private AI meeting notes. Free and open source." Transcribes with whisper.cpp or, on supported Macs, Apple SpeechAnalyzer, and summarises with a local open-weight model through llama.cpp. "Meeting data stays local; Yogurt goes online for model downloads and update checks." Apple Silicon, macOS 14.4+, 8 GB memory. Flags: setup downloads about 5 GB, then up to 14 GB or more; its MCP access is off by default, and when on, the assistant app "may send what it reads to its own online model"; telemetry isn't mentioned, which isn't the same as none. Dave: this is the first notes app that fits your rule that client words stay on the Mac. Test it on one call of your own (a roleplay, not a client), compare the transcript with what Wispr Flow gives you, and leave its MCP switch off. ↗ · HN
  • [repo] agent-desktop (vercel-labs/agent-desktop; Apache-2.0; 22.9k★, about +6.4k this week; v1.3.0 on Nov 12) — "agent-desktop gives an AI agent computer use without screenshots or pixel matching." It reads a Mac app's accessibility tree as JSON with a ref for each element. Ships a skill (npx skills add https://github.com/vercel-labs/agent-desktop --skill agent-desktop) and an MCP mode (agent-desktop mcp); v1.3.0 adds a macOS VM sandbox. Flags: it needs the Accessibility grant, which lets it read and drive every app; "Snapshots, clipboard reads, screenshots, command output, and debug artifacts can contain private desktop content."; star counts came through a summary. Dave: it is the Mac-side twin of phone-harness, and reading the tree is cheaper than screenshots. Don't grant Accessibility on the main Mac account for a trial. If you want it, the VM sandbox is the place, and any action it takes in a real app needs a rulebook line first. ↗
  • [repo] free-claude-code (Alishahryar1/free-claude-code; AGPL-3.0; 69.5k★, trending daily) — a local proxy that routes Claude Code and other harnesses to models from other providers; installs by piping a script from GitHub into sh. Its own README: "A failed request may reach and consume usage from more than one provider before succeeding." Dave: skip it. Everything a session reads (client profiles, canon, keys in context) would pass through a proxy you haven't read, to whichever provider it picks. ↗
