  • [skill] "Prompting Claude Fable 5.2" (Anthropic docs; quoted by Simon Willison, Nov 10) — the model's own prompting guide. Effort: "Start at high, the default on the Claude API" (Claude Code defaults to medium), and "rerun your effort sweep instead of carrying over a setting you tuned on Claude Fable 5.1 or Claude Opus 5.5". At high and above it "thinks before almost every reply, including a reply to a greeting". Approvals: "name the exact actions they cover, because the model applies them as written". Long runs: "Cautious instructions build up wherever context carries over", so remove stale notes and name the steps that are safe to retry. It "sometimes ends a turn before the work is done"; the doc's fix text raised output tokens about 30%. It "follows style rules closely", so hard caps like short sentence limits can make prose choppy. An optional line, "This codebase is yours: what it's for and how it's built are your call, and you'll keep building on it", got repeated code merged in about half of small tasks against under a tenth, at about 1.5x the output tokens plus unrequested tests and docs. Flag: every figure is Anthropic's own small-task testing. Dave: four edits for any Fable seat. First, write approvals in KICKOFFs as exact actions ("send rows 1, 2, 4"), never "go ahead", so a "your OK" reaches only what you meant. Second, prune before a Fable seat inherits a STATE file: your session-start check already flags orchestrator-ops/STATE.md at 262 lines and 140 KB, which is the build-up the doc describes. Third, run one decision seat at medium and at high and log the result as a dated row in route-compute's evidence.md. Fourth, use the "yours" line only on new builds like ~/sales-copilot, never on live portal fixes, and add the early-stop text only to lanes you've seen stop short. ↗ · Willison
