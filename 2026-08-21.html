Claude skills / plugins / MCP

  • [skill] Claude Code 2.1.238 (Aug 20) — a 39-change release, and two of them matter more to Dave than the headline features.   • [skill] activeing123/mcptoon — Apache-2.0, zero-dependency, pip install mcptoon (~250KB): a CLI that keeps MCP tool schemas on disk (~/.mcptoon/config.json) instead of in the context window, so the agent runs mcptoon shell commands rather than connecting to servers. Claimed savings are per-format: 255 tools cost 117 tokens in compact/names-only mode versus 90,804 as JSON schemas (99.9%), 6,174 tokens in slim mode with schemas (93%), and 30–40% on results via TOON encoding — measured with tiktoken's cl100k_base, i.e. their own benchmark, not an independent one. GitHub repos & OSS tools

  • [repo] volcengine/OpenViking — ByteDance's Volcano Engine open-sources a "self-evolving context database for AI agents" (31.4k★, +950 today): memories, resources and skills live as one virtual filesystem under a viking:// protocol, so the agent browses its own context with ls, tree and find instead of querying a black-box vector store.   • [repo] Huzzah (Show HN, 332) — an experimental editor built on one inversion: coding-agent prompts today are longform, imperative and transient, and Huzzah makes them pseudocode, declarative and persistent. Prompts are never discarded; they become a maintained central authority expressing what the human wants from the machine. The author's motivation is two failure modes he hit working almost exclusively with agents since January — the tedium of writing full sentences for every change, and agents confusing themselves past a certain codebase size. Dave: this is the same insight his skills already encode (a skill is persistent instruction, a chat message is transient), pushed one level further — and it's the clearest available argument for why a rejected draft should become a rule in a plugin's knowledge file rather than a correction typed again. ↗
  • [repo] zachahn/vomit (HN 266) — GPLv3, fully local, no telemetry: pipes Claude's output through a separate small LLM running on your own machine (Llama.app or Ollama) and rewrites it into plainer English, either replacing Claude's display or running alongside it non-invasively. The author is honest about the limits — the local model only sees what Claude said, not what it did, it's slow, and it's barely tested outside macOS. Dave: he does not need this (that's what an output style is for, and 2.1.238 just fixed styles drifting), but it's the sharpest artefact yet of the verbosity backlash that's been compounding for a week — someone would rather run a second model locally than read the first one's preamble. ↗
