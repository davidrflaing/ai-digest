  • [skill] Claude Fable 5.2 is now the default Fable model in Claude Code (Anthropic, Nov 9; Claude Code 2.1.321; HN 467 / 741) — model ID claude-fable-5-2. It costs 8/40 per million tokens (Fable 5.1 was 10/50) and is "up to 30% faster than Fable 5.1". "Medium is the default in Claude apps and Claude Code." Anthropic says that at High effort it "scored about level with Opus 5.5 at Max effort" on FrontierCode 2.0, "for roughly half the cost per task". From the changelog: "Saved Fable 5.1 picks move to fable; use /model claude-fable-5-1 to switch back." Fast mode is 2.5x faster at twice the price; in Claude Code it "will bill through extra usage credits". Plan allowances: Ultra and Team Premium get one to three Fable resets depending on how long you've subscribed (under 6 months: 1; 6–12 months: 2; over 12 months: 3), "use them anytime by March 8". Pro and Team Standard get a week at up to half the weekly limit, plus one reset. On the API, both models require 30-day data retention and aren't available under zero data retention unless Anthropic authorises it. A request that edits system, tools or an earlier message and then sends a thinking block back now gets a 400 on every account. Flags: Every's review (Dan Shipper) grades it S-plus for coding but B for everyday email and documents and B/B-plus for writing ("buries the lead"). One of its testers says it "stops too early at medium effort". AINews notes it uses more tokens, so SemiAnalysis's cost per task rose from $67.16 to $88.15 despite the price cut. Cyber- and bio-flagged requests fall back to Opus 4.8 or Opus 5. Dave: this is a model launch, so route-compute's references/evidence.md is due its re-check. Three things to do. First, any lane or KICKOFF Compute line that says fable now gets 5.2 at medium effort unless you set the effort; write the effort into the decision seats (high where the judgment is the deliverable). Second, keep the drafting seats (dave-voice, broadcast, comms) off Fable, since the reviewers grade its writing B. Third, leave fast mode off in the picker: it bills extra usage credits, which is spend. If you're on Ultra (the old Max 20x), note how many resets you got and the March 8 date. Before an API lane that handles client words moves to Fable 5.2, check its retention terms. ↗ · plans · HN · review
  • [skill] Claude Code 2.1.321's other changes (changelog, no dates on entries; 2.1.322 only adds fast mode on Vertex) — the email check from Nov 3 now refuses "only a shell command that holds your email and names a User-Agent, without asking, so other commands and scheduled runs no longer stop at its prompt". Mods' own tool calls ($.tool.call, $.mcp.call) now "raise no prompt even under your own ask rules or in dontAsk and -p runs"; deny rules and organisation policy still apply. In exchange, mods no longer switch themselves on in auto and bypass modes, and don't load at all in dontAsk. Security fixes: MCP sign-in was "sending secrets such as refresh tokens to another host when a server redirected them"; a read-only Bash command could run "outside the sandbox without a permission prompt"; deny rules missed the file a cp or mv into a folder writes. Also: claude -p had been telling Claude that background commands get 30 minutes when they stop after 10 (fixed). Headless sessions now reload .claude/skills mods when the files change (CLAUDE_CODE_PLUGIN_DIR_WATCH=0 turns that off). .claude/skills folders inside ~/.claude/plugins "no longer load when Claude works on files there". claude remote-control --settings <file> applies one settings file to every session it starts. Flags: your account email is still in context (this run's context still carries your account address); the changelog shows the check narrowed, not the removal from context that Anthropic promised on Nov 6 for "early next week". Dave: update for the sign-in fix alone, since your Notion, Gmail and Gemini connectors all use MCP sign-in. The mods change means a mod's own tool call now skips your ask rules, and the changelog names only deny rules and policy as still applying. So check once that rulebook-nevers.py (the C9/E3 block) still fires on a mod's tool call, and if it doesn't, put those two lines in deny rules as well. ↗

GitHub repos & OSS tools

  • [repo] Flide (OmniJev/Flide; Apache-2.0; 305★, 28 commits; 0.1.0 on PyPI Oct 24, 0.1.11 today) and Amazon's Strands Decider write-up (Nov 9; HN 86) — Flide is "the extremely fast inference engine for decision model". It "serves the Jev /v1/systemone API": you post a state and questions and get a probability for each option back. Its demo asks 8 questions of 10,000 emails in 28 seconds on one H200 with a 0.8B model. On the same day, Amazon's Strands team said it moved internal ticket labelling (20 categories) from Sonnet 4.6 to a Gemma-based decision model: 897 ms against 4,215 ms per call, 2,010 tokens against 6,724, about $0.0005 a ticket against $0.0222 ("about 44 times cheaper"). Flags: Flide's "9.5x faster than vLLM" headline uses a different baseline from its own table; the page doesn't say who OmniJev is or how it relates to TypeSafe; the demo needs a datacentre GPU and this run didn't check Mac support. Amazon's post is a vendor blog with no accuracy figures beyond "performed just as well", and key order in the JSON moved its probabilities by up to 0.19. Dave: don't install Flide. Take the Amazon numbers to route-compute's evidence.md as a dated row (vendor-graded). It backs the first fork, "needs a model at all?": labelling jobs such as the aggregator's priority and banner calls are decision-model work, which is what your Jev / TypeSafe calls already are, not a Sonnet seat. The key-order finding is worth a test in your own Jev code: shuffle the option order once and see if the answer moves. ↗ · Amazon · HN
