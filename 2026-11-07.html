  • [skill] "The components of agent memory" (Anthropic Engineering, Lance Martin, Nov 6; HN front page) — Anthropic's own measured advice on agent memory. It describes four layers: "transcripts (a searchable event log)", "memory notes written by Claude", "memory representations such as wikis", and "injected context loaded into every session". A "dreaming" pass works across them. The findings that matter for you: (1) "it helps to tell Claude what memory is for, but not how to use it". A rigid "record only failures" rule cut the memory gain for Opus 5 and Opus 4.7. (2) Store what can't be re-read from the environment: Sonnet 3.7 wrote 413 memory files in Pokémon, mostly things already on screen; Fable 5 wrote nine. (3) Keep the injected layer small: "an incorrect note can be carried into every session". Claude Code's auto memory loads only the first 200 lines or 25 KB of MEMORY.md, and the post cites "longer instruction files reduce adherence". (4) One page per entity, with terms quoted word for word, kept 57 of 57 facts; one shared file kept 41 of 57. (5) "Dreaming gives Claude a way to test its notes against the original transcripts". In a Pokémon run it found and fixed a wrong note. With memory, Opus 5.5 went from 0.655 to 0.838 on CL-Bench's database task. Flags: Dreams on the Claude Platform are a research preview behind "Request access". They're API-only (no Claude Code mention), billed at normal token rates, and "not eligible for zero data retention or HIPAA". The numbers are Anthropic's own evals. Dave: three moves. First, client profiles already have one page per person, so keep the client's own words quoted there, not paraphrased; the 41-vs-57 result is the case for it. Second, your save rule ("would it change a decision outside this lane? could a script check it?") describes what memory is for, so it's the kind the post found helps. Leave it. Third, everything past line 200 or 25 KB of a MEMORY.md is silently not loaded. Add a line to checks-to-build.md that flags any memory/MEMORY.md over 200 lines or 25 KB. Don't send client transcripts to Dreams (no ZDR). Your weekly canon-lag run is already a dream of this kind: notes checked against their sources. ↗ · Dreams docs · HN

GitHub repos & OSS tools

  • [repo] CloneGuard (tharun208/cloneguard; MIT; Go, no dependencies; 16★; Show HN 29) — "Scan a repo for credential-stealing tricks before it runs." cloneguard clone <url> or cloneguard scan ./dir. It looks for secret theft (SSH keys, cloud credentials, shell history, browser passwords, env dumps), exfiltration endpoints (Discord and Telegram webhooks, pastebin, raw IPs, base64-hidden URLs), download-and-run patterns, and auto-run hooks (npm install scripts, .vscode/tasks.json, setup.py). Exit codes run 0 (clean) to 3 (dangerous). "It only reads files. It never runs, installs, or imports anything." Flags: it does NOT check .claude/settings.json hooks, .mcp.json, skills or git hooks, which are the routes that matter for Claude Code (the Postman and trojanized-extension cases); three commits, first released Nov 3; pattern-based, and "'No red flags found' is not proof of safety". Dave: worth having as a first pass before you read any repo a digest features. Build it from source after reading its Go (no dependencies, so it's quick to read). The rules sit in one list (lineRules in rules.go), so a lane could add a .claude/ and .mcp.json rule set, the gap that matters for you. It doesn't replace your read-before-install. ↗ · HN
