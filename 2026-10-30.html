Claude skills / plugins / MCP

  • [skill] The trojanized Claude Code editor extension, anthropic.claude-code 2.1.313 (Oct 29–30; HN 153 / 22 and 124 / 18 on today's front page; Cursor's notice; four advisories) — a malicious 2.1.313 of the official extension was in Cursor's extension marketplace from 02:27 to 13:35 Pacific on Oct 29 (04:27–15:35 Bogotá) and on Open VSX, the registry Cursor, Windsurf and VSCodium install from (no publish time given there). Cursor: "This malicious version of the extension was not developed by Anthropic", "at most 5,000 users", and no evidence that other versions or the official distribution are affected. It runs as soon as the editor loads the extension; you don't have to open Claude. It appends an Ed25519 key with the comment svc-telemetry to ~/.ssh/authorized_keys, tries to turn on Remote Login, opens a reverse SSH tunnel to 134.209.82.225, installs a fake Apple LaunchAgent (~/Library/LaunchAgents/com.apple.sysmond.plist, which starts ~/.config/.smt), and beacons your hostname, username, git email, and the names (not the values) of up to 40 environment variables containing KEY, TOKEN, SECRET or PASS. Uninstalling it removes none of that. Check (three commands): grep svc-telemetry ~/.ssh/authorized_keys · ls -la ~/.config/.smt ~/.config/.smtk ~/Library/LaunchAgents/com.apple.sysmond.plist · cursor --list-extensions --show-versions | grep -i claude (repeat with windsurf and codium if you have them). Any hit means treat the Mac as compromised: delete the key and the files, then rotate every token whose name the beacon could have sent. The fix is 2.1.314. Honest flags: the Microsoft VS Code Marketplace and the npm CLI aren't confirmed affected (the CLI changelog goes from 2.1.312 straight to 2.1.314; one advisory says a 2.1.313 was pulled from npm and the VS Code Marketplace, another found it was never listed there); nobody knows how the attacker got publish access (the Open VSX namespace belongs to an Anthropic employee); Anthropic has made no statement; Phorion found a bug that makes the Remote Login step fail without admin rights, so on a Mac where Remote Login wasn't already on, the tunnel leads nowhere, but the key and the LaunchAgent still land. Dave: your lanes run the CLI in cmux, which nothing so far says is affected. The exposure is only if Cursor, Windsurf or VSCodium with the Claude Code extension was open on this Mac on Oct 29–30. This run can only read ~/ai-digest, so the check hasn't been done; it takes 30 seconds and it's yours to run. ↗ · Cursor · Timeline · Checks · HN
  • [skill] Claude Code 2.1.314 (on npm at 00:12 UTC Oct 30; there is no 2.1.313 in the CLI changelog) — the lines that touch your setup: claude -p no longer exits 0 with no output when it fails at startup; it prints the error and exits 1. permissions.blockWritesOutsideWorkingDirectories makes Write, Edit and NotebookEdit refuse paths outside the working directories in every permission mode (Bash isn't covered). Hooks that match Bash now also run on commands the Monitor tool starts (they can block or ask, but not approve or rewrite), and hook if conditions such as Monitor(tail *) match the way Bash(tail *) does. PreCompact hook output is cut at 10,000 characters. ~/.claude/skills/.trash and ~/.claude/plugins/.trash no longer grow without limit (about 1,024 entries each), and the skill watcher stops checking every removed skill. Long headless or SDK turns with many subagents use less memory. "Continue automatically at usage limit" no longer keeps going past three continuations. A session that starts with a skill is titled from it. Flags: the changelog has no dates; Bash hooks on Monitor commands can't approve or rewrite them. Dave: this job already stamps output=missing when claude -p writes nothing, and from now on the log will also say why. Check that consider-this's 08:30 script reads the exit code, not just whether output appeared. If rulebook-nevers.py matches on Bash, it now also sees commands a lane starts through Monitor. The new write block is worth setting in the launchd jobs, because a digest run has no reason to write outside ~/ai-digest. ↗
