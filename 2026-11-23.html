GitHub repos & OSS tools

  • [repo] Taskless (taskless.io; CLI is MIT; Show HN 6 / 2, Nov 22) — "Taskless creates rules for your agent harness. You tell Taskless what you want, and Taskless figures out how to enforce it." Your own coding agent writes each rule ("Rules are generated using coding agents"), and Taskless compiles it to whatever can decide it: "a syntax tree, the prose itself, your own linter, or a check that reads across files", running on ast-grep and Vale. Every rule "compiles to a deterministic check with its own tests. No model in the loop when it runs." Install: npx @taskless/cli. It "runs locally, and needs no account", and "Detects Claude Code, Cursor, and OpenCode." It runs on each commit, PR or CI step. Flags: anonymous telemetry is on by default and "collects CLI version, OS, the repo's org/owner, and a bit about the repository"; turn it off with TASKLESS_TELEMETRY_DISABLED=1 or DO_NOT_TRACK=1. Taskless Cloud sees your code "Only when you ask it to. Tagging @taskless on a PR is an explicit request." The maker says the docs site is "in sync with neither" the CLI nor the Cloud app. One user report on HN, about two months of use in CI. Dave: this is today's pick. Your memory rule sends every "a script could check this" lesson to checks-to-build.md for 🏛️. The file holds about 200 lines, and each goes in "only after it is shown failing on that mistake". Taskless's per-rule tests are that bar. Several lines are code shapes ast-grep can match. One is the 12 Oct line: every GoHighLevel conversations reader reads direction as x.direction || x.meta.email.direction. Another is the 13 Oct line: no hook does readFileSync on a transcript without a size guard. Hand 🏛️ the tool for one of those lines in ~/comms, with telemetry off and never an @taskless tag on a PR. If the rule catches the old bug in its own test, that's one line off the list. Canon and retired-phrasing checks stay with audit-surface.ts; don't build a second copy in Vale. ↗ · HN
  • [repo] Aaf-gate (buberlo/aaf-gate; Apache-2.0; Show HN 3) — "Deterministic policy gate, kill switch, call limits and tamper-evident audit for existing AI agent runtimes (Hermes Agent). Python stdlib." It sorts tool calls into classes (read, draft, internal_write), stops everything on gate-stop, and keeps a hash-chained SQLite audit log. Flags: Hermes Agent only, with no Claude Code adapter ("Adapters can target other runtimes later"); "It is not production-ready"; the maintainer "is not actively maintaining it". Dave: skip it. rulebook-nevers.py is your gate, and the comms send ledgers already keep the record. ↗
