  • [skill] Claude Ship and /ship (Anthropic, beta, Nov 23; /ship needs Claude Code 2.1.330+, GitHub CLI 2.63+, git 2.38+) — two different things share the name. Claude Ship is three agents, Code Review (generally available), PR Steward (beta) and Claude Approvals (beta), and "Claude Ship is for organizations on Team and Enterprise plans". Each agent "is billed on token usage through your organization's usage credits, separately from your plan's included usage." /ship is a CLI command that "counts as regular Claude Code usage", and its docs name no plan. /ship commits your work, pushes the branch and opens the PR "as you". It runs /code-review, then watches the PR for up to seven days, pushing fixes for failing checks, conflicts and comments. Flags, all from the docs: "/ship proceeds with no confirmation prompt" (an "Esc to cancel" line, then it carries on after a few seconds); it writes the commit message from the session transcript, and "Anyone who can see the pull request can read that message"; it "looks for secrets by file name, such as .env", and a deny rule "doesn't keep a file out of the commit"; the watch uses your own gh and git sign-ins, so "it could merge a pull request that your repository's branch rules let you merge". On a solo repo with no branch rules, that's every PR. Dave: today's pick is a rule, not an install. The rulebook has no line for a lane pushing a branch and opening a PR. G23 says new work reaches a GitHub copy "only through the same scan (tools/repo_copies.py)", and /ship pushes around that scan, with a message written from a transcript that may hold client words. Treat /ship and /steward as ask-first in every pane, 🎯's typed commands included, and tell 🏛️ Agent ontology so it gets a line. A suggestion for that line: your OK each time, private repos with no client data only, after repo_copies.py has run. The three agents need a Team or Enterprise organization, so there's nothing to switch on. ↗ · /ship docs · Approvals · bcherny
