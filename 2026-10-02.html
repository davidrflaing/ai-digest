Claude skills / plugins / MCP

  • [skill] Claude Code 2.1.287 (Oct 1, 106 CLI changes): Mods are out for everyone. A mod is a plugin made of JavaScript/TypeScript handlers that run inside Claude Code, so it can draw a pane or a band above the prompt, add a /command that runs with no Claude turn, and hold, rewrite or answer a tool call — the docs put it as "A mod is a plugin that changes how Claude Code looks and behaves." Mods are on by default from 2.1.287, install with /plugin, and you can ask Claude to write one (the built-in plugin-authoring skill). Hooks also run in claude -p, cloud sessions and Remote Control, but only the terminal and the Desktop Code tab draw anything. Honest flags: "Mods aren't sandboxed." A mod can read your files and keys, and one that approves tool calls can approve a call "that one of your own PreToolUse hooks blocked", which includes the rulebook-nevers block. Dave: run claude plugin validate <dir> on any third-party mod before installing, because it lists the mod's hooks and calls without running it. Two first builds worth asking for: a band above the prompt that shows the workspace's model and effort (the check the orchestrator does by eye after each launch), and the running comms board as a pane so it stops being re-rendered in the transcript. Same release: a dangerous rm no longer loses its always-ask prompt when the command also redirects output, and a folder's CLAUDE.md is no longer attached twice after a resume or compaction. ↗ · changelog · X
  • [skill] "You should know" (built-in mod, off by default): "a side agent watches your back and flags things you or Claude might miss", shown as a note above the prompt during longer tasks — turn it on with /plugin enable cc-plugin-you-should-know@builtin. Honest flags: the changelog limits it to "first-party sessions with telemetry on", and a side agent spends usage on every long task. Dave: enable it in one long build workspace (allowing-app or sales-copilot) for a day and see whether its notes catch anything the lane missed before turning it on board-wide. ↗
  • [skill] anthropics/claude-code-playground sample mods: token-weather (a context-window forecast above the prompt with a sparkline of the last 12 turns), blast-radius (holds a risky shell command such as rm -rf or a force push and shows what it would change, with proceed and cancel buttons), and replay-theater (/replay steps through the last turn's file edits) — shared "as they are, without support". Load one for a single session with --plugin-dir before keeping it. Dave: blast-radius is the one to try first, on a workspace that touches a live repo (ocd-portal). It's also the working example to copy for any rulebook "your OK" action you'd like shown as a button instead of a typed yes. ↗

GitHub repos & OSS tools

  • [repo] weave-os/router (Weave Router 2.0): a local proxy on localhost:8080 that sits under Claude Code, Codex or Cursor and picks a model for each request, across Anthropic, OpenAI, Gemini and OpenRouter models (Apache-2.0; 5.5k★; Show HN 105) — install with npx @weave-os/router --claude (hosted) or make install-cc (self-hosted). It claims GPT-6 Astra's pass rates at 52–54% of the cost and 2.2–2.5x faster. Honest flags: the benchmark is their own, HN commenters point out that switching models mid-session throws away the prompt cache, and it routes prompts to whichever providers you enable. Dave: this does by machine what route-compute does by rule, and it overrides the per-seat model pins. Don't put it under the board. If you test it, use one throwaway coding workspace with Anthropic models only, and compare the bill for the same task. ↗
  • [repo] mvschwarz/openrig: define a team of coding agents in YAML and start it with rig up. It runs Claude Code and Codex together on tmux, with rig send and rig broadcast messaging, snapshot and restore, and an MCP server (Apache-2.0; 4k★, +691 today) — install with npm install -g @openrig/cli. "Define your agent team in YAML, boot it with one command." Honest flags: it's v0.6, macOS/Linux only, and it's another orchestrator beside cmux + workspace-manager. Dave: don't adopt it. The idea worth borrowing is a snapshot of the whole team's state in one file, which is what active.json plus stash.json do in two. ↗
