Claude skills / plugins / MCP

  • [skill] Stageshow (benjitaylor/skills; 662★; posted this weekend by Benji Taylor, X's head of design; npx skills add benjitaylor/skills --skill stageshow) — a skill for faux product UI that reads as a real product: stills, feature cards, bento grids and short cursor demos, built in React from a kit of parts and "gold" examples. It works in seven steps: pick still or animation and the size it'll be seen at, map your product's tokens onto the kit's theme, plan three to five beats (10–16 seconds, every cursor move has a reason), build with a small budget of real text, then film it with scripts/film.mjs, review every frame and write a REHEARSAL.md before handing over, so the agent checks its own output. "These are authored illustrations, not browser automation." Honest flags: no repo-level licence (each skill carries its own, so read the folder's); one skill only; the page doesn't say what the film script needs (browser, ffmpeg); Taylor himself expects models to make it unnecessary soon; no independent tests, only X praise. Dave: this is for the Allowing launch's marketing visuals (landing-page feature cards, a looping demo for the app's sales page, ad statics that show the app), fed from ~/allowing-app/design-system/tokens.json at step 2. Because it's drawn, not screenshotted, no client data can end up in it. Two limits: don't use it for App Store screenshots (Apple wants the app in use, so those stay real captures, e.g. via Winch or App Store Screenshots), and don't draw a feature the app doesn't have, because in an ad that's a claim. Any framework words on a mock screen go through /copy-claims. ↗ · post
  • [skill] agent-desktop (vercel-labs; Apache-2.0; 7.9k★, +2,243 today, #1 on GitHub trending; v1.0.2 Oct 30, announced Oct 31; npm i -g agent-desktop, then npx skills add https://github.com/vercel-labs/agent-desktop --skill agent-desktop) — Vercel's agent-browser idea for the whole computer. A Rust CLI that reads native apps through the OS accessibility tree and acts on elements by reference, not by guessing pixel coordinates from screenshots. It can drill into one part of a window to save tokens, runs in the background while you keep working, and lets several agents work at once, each with its own cursor. macOS, Windows and Linux; on the Mac it needs Accessibility permission (agent-desktop permissions --guide). Honest flags: its own README warns that snapshots, clipboard reads and screenshots "can contain private desktop content"; an optional helper sends screen descriptions to a model provider; a commenter notes that accessibility trees fail on canvas and badly labelled Electron apps, which sends you back to screenshots; one Windows tester preferred Windows-MCP; Homebrew isn't out yet. Dave: where a lane now uses the computer-use skill on a Mac app with no API (screenshots plus clicks), this reads the same window as a list of named buttons and fields: fewer tokens and fewer missed clicks. Accessibility permission lets it read every open window, so use it in a build lane with no client chats on screen. Never point it at WhatsApp Desktop: the WhatsApp lane stays on the official web client in its own profile, read-only, because opening a chat sends a read receipt. ↗ · launch

GitHub repos & OSS tools

  • [repo] Friday (splashxmoon/friday; MIT; 14★; on Product Hunt today as "Friday Work"; Mac, Windows, Linux; npx github:splashxmoon/friday) — a local app that runs several coding agents on one repo (Claude Code, Codex, Cursor, Gemini CLI and anything that speaks ACP), each in its own git worktree, with a shared task board. Tests run when a task finishes, and another agent reviews what the tests don't settle. When one agent hits its usage limit, "the agent best placed to finish picks up where it stopped" with a record of the files read and every command run, pass or fail. It uses each tool's own sign-in, "never switches your accounts for you", and listens only on 127.0.0.1. Honest flags: 14 stars, 46 commits and no release yet; anonymous usage counts go to PostHog by default (off with FRIDAY_NO_TELEMETRY=1); the Windows build is unsigned; the "21% fewer tokens than starting over" figure is the maker's own, from 14 tasks on an earlier version. Dave: route-compute already has an IF TIGHT line and the codex seat. What the board lacks is the hand-off record when a build lane hits the weekly limit halfway through. Try it on one build repo with telemetry off. Keep it off any lane with client words in it, because the agent that picks up can be a different provider, and that provider gets everything the first one read. The same idea from beacon.sh (#1 on Product Hunt today) captures every agent trace into shared memory, and its thread has no answer yet on whether API keys in command output are removed first, so skip that one. ↗ · PH
