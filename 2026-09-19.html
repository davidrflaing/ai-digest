GitHub repos & OSS tools

  • [repo] Laya: an Apache-2.0 "decision model" (421M) that answers choice, score and yes/no questions about a message with calibrated probabilities and an escalate flag, and never writes text (Convai Innovations; HN 167 today) — pip install laya, then laya.load("convaiinnovations/laya"). You give it a state (an email, a ticket, a JSON document) and typed questions. It returns the chosen option with a probability for each option, plus an act-or-escalate output. It's built on ModernBERT-large, takes 32.8 ms per question on one GPU, also runs on CPU, and has a 322M multilingual version covering 100+ languages. Convai's numbers: 0.766 on the typed-decisions test, against 0.727 for TypeSafe Jev 1.13.0 (Sept 16), with a calibration error of 0.081. Honest flags: the makers say the base model scores near random (~0.35) until you fine-tune it on your own labelled data. Accuracy falls apart past 20 options, and the benchmarks are Convai's own. Dave: the comms board's 🔴/🟡/⚪ call is a three-option question with an escalate case. The priority corrections already logged through the aggregator's :learn loop are a starting label set. Fine-tune on those, then run it in shadow beside the nightly pass for two weeks. It runs locally, so client messages stay on the Mac. Only look at items it escalates with high confidence that the board marked ⚪. Treat it as a second opinion, not a replacement for the Claude pass. ↗
  • [repo] Cactus Needle 3: on-device models of 8–29 MB for tool calls, structured extraction and embeddings (Apache-2.0; Sept 17; HN 207 / 89; 11.4k★) — pip install cactus-needle. You declare tools as Python functions: the signature gives the argument types and the docstring gives the description. Needle picks which tools to call and fills in the arguments from what the user said. Two requests get two calls, in order, and a request no tool covers gets an empty list instead of a guess. The same 2-bit weights ship at every depth from 2 to 20 layers, and they run on iOS, Android, macOS and WebAssembly. LoRA fine-tuning is one command (needle finetune data.jsonl --epochs 10), and 200 examples raised scores by 18–36 points on DroidCall. Honest flags: it has no general chat ability by design, React Native bindings aren't documented, and the benchmarks are Cactus's own. Dave: the Allowing app is where a model this small could matter: turning a typed entry into fields on the phone, with no server call. Keep it out of anything that decides whether someone is in crisis. An 8 MB model shouldn't be the thing that routes SOS. ↗
