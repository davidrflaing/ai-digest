Claude skills / plugins / MCP

  • [skill] Claude Code 2.1.269 (Sept 11) — claude plugin eval: the first way to measure whether a plugin is actually earning its context — the command runs a plugin against realistic prompts you write, grades what Claude produced, and by default runs every case twice — a with-arm where the plugin is loaded and a without-arm where it isn't — so what you read is Δ, the difference the plugin contributed, not a score in a vacuum. Six grader types: four cost nothing because they're computed from the transcript and the files on disk — regex, tool_used, tool_order, file_exists — and two call a judge model and add to the bill: llm (scores the reply against prose criteria you write) and baseline (compares against a reference answer); results come back as JSON and an HTML report, and the exit codes make it a gate: 0 when nothing scored below --threshold (default 1.0), 1 when something did, 2 when the --max-cost-usd ceiling was hit, with partial results reported. Also new: /output-style [name] to list and switch output styles, including over Remote Control and in cloud and headless sessions; CLAUDE_CODE_WORKFLOW_MAX_CONCURRENT_AGENTS (1–256) to raise the Workflow tool's per-run fan-out; OTEL_METRICS_INCLUDE_REPOSITORY to tag OpenTelemetry metrics with vcs.* attributes; a diff of the files a Bash command changed attached to the tool result (bashEditDiffEnabled); and two more prompt-cache repairs — a response cut off at the output-token limit was partially invalidating the cache on the next turn, and resuming after interrupting Claude mid-thought could change how earlier context was re-sent. The containment fixes are the week's third round and the ones to read twice: Edit() deny rules and the write-path check were not applying to the file a Bash tee command writes, and a Bash(tee:*) allow rule no longer covers destinations outside the working directories; a deny or ask rule starting with ! was applying beyond the settings source that wrote it (it's now scoped to its own source, and a bare ! negation is ignored); permission_denials in --output-format stream-json was omitting Read, Edit and Write calls blocked by a path-scoped deny rule — i.e. the machine-readable audit trail was under-reporting; and plugin archives extracted for a session were readable by other local users, kept world-writable bits from the archive, and stale files survived re-extraction. Plus: the git status Claude is told after a compaction is now the current one rather than the session's opening state; /goal now retries with backoff or pauses and says why instead of silently stalling on API errors and usage limits; /btw answers that contained made-up tool calls are flagged as not executed; sessions stuck permanently on "Prompt is too long" when auto-compaction had nothing to summarise; the attribution reminder was overriding a CLAUDE.md or memory rule against commit and PR attribution; and /ultrareview --post now posts the PR comment directly instead of starting a second cloud session. Dave: this is the measurement /skill-doctor and the context-rot argument (Sept 8) have both been standing in for — 20+ plugins loaded every session and no number on any of them; four of the six graders are free, so a first pass over the comms and delivery skills costs nothing but the writing of the cases, and the honest first question isn't "did it score well" but "was Δ positive at all". Two days before the Sept 14 trim, a CI gate on plugin quality is also a token gate. ↗

🔬 Research

  • 25 Fields Medallists sign a declaration against how AI labs are doing mathematics (Sept 11; HN 996 / 946) — published at mathandai.org and on Terence Tao's blog as "A Severe Misalignment of AI in Mathematics", signed by Tao, Peter Scholze, Maryna Viazovska, Caucher Birkar, June Huh, Martin Hairer, Maxim Kontsevich, James Maynard, Manjul Bhargava and 2026 medallist Yu Deng among others, spanning Fields classes from 1978 to this year. The claim is one of objective misalignment, not capability: what the labs optimise for is true statements produced faster, and what mathematics is for is conceptual understanding, insight and the training of new mathematicians — so rushed AI-generated solutions raise attribution and plagiarism problems, bypass the human processes of discussion and dissemination through which knowledge actually becomes knowledge, and damage the ground new ideas grow in. The declaration frames it explicitly as an instance of a broader misalignment already reaching other scientific and creative professions, and society at large. TechCrunch's headline on the same day: OpenAI's feud with mathematicians is escalating. Dave: the two weeks of Navier–Stokes and Hodge items (Sept 9, Sept 11) end here, and this is the same sentence his own canon makes — Tao's earlier line that solving the problem is a proxy and the understanding is the product is now twenty-five signatures; the transferable version for a coach is that a client's insight is not a faster-produced true statement, and a framework explained by a machine to someone who didn't work it through hasn't landed. ↗
